# 生成经验（现象 → 真因 → 修法 → 代码锚点）

> 这份文档存在的理由：这些坑**都已经在代码里修好了**，但理由曾经只活在 README 里，
> 重写文档时被整段删掉，于是后来的人（或 AI）看到一行奇怪的权重、一个奇怪的判据，
> 只会觉得是随手写的，删了就再也回不来。
>
> 规则：**每条都必须是"现象 → 真因 → 修法 → 代码锚点"四段齐全**；代码处加一行注释指回本文编号。
> 新增经验时先写现象（能看到什么），再写真因（为什么），最后才写改法。

---

## #1 `--disable-pinned-memory` 缺失 → 出图从 42 秒劣化到 15 分钟以上

- **现象**：第一步飞快（tqdm 一跳到底），然后忽然掉下悬崖，十几分钟才出图；显存看着够。
- **真因**：缺 `--disable-pinned-memory` 时 ComfyUI 走 pinned memory，Windows 上会触发换页/搬运抖动，前面几步是缓存命中，之后每次都要真正搬运。
- **修法**：启动参数强制加 `--disable-pinned-memory`（连同一个 `--disable-async-offload` / `--disable-dynamic-vram` / `--cache-*` 组）。
- **代码锚点**：`lib/index.js` → `CONFIG_DEFAULTS.extraComfyArgs`。

## #2 `832×1216` 会画成两个人

- **现象**：竖图里出现两个人物（或人物加一个残影）。
- **真因**：这个宽高比落在训练分布的边缘，模型用它最省事的方式补齐画面——复制一份主体。
- **修法**：竖图改用 `896×1152`（或 `1152×1344`）；尺寸表里保留 `832×1216` 但标注禁用原因。
- **代码锚点**：`lib/app.js` → 尺寸表 `["竖 832×1216", 832, 1216]` 那行。

## #3 决定视角的是"姿势"，不是"相机段"

- **现象**：提示词写了俯视/仰视的相机段，出图视角却纹丝不动；反而是加了 `head tilted`、把手举到脸边之后，视角被钉死在俯视近景。
- **真因**：模型对**身体姿态**的响应强度远高于对"镜头术语"的响应；姿态词会连带改写机位，机位词单独写几乎无效。
- **修法**：要多视角就写姿态（`lying`、`looking up`、`from below` 配姿态），不要只堆相机术语；反过来，要固定视角就先固定姿态。
- **代码锚点**：`lib/app.js` → 视角词表 `["俯视", "from above"], ["仰视", "from below"]` 那一行。

## #4 `/free` 返回空 body，按 JSON 解析会抛错

- **现象**：卸载模型后请求报 `JSONDecodeError`，但模型其实已经卸载成功。
- **真因**：ComfyUI 的 `/free` 成功时返回 **空 body**（不是 `{}`）。
- **修法**：`/free` 用"不解析响应"的 POST（`_http_post_nojson`），只认状态码。
- **代码锚点**：`sidecar_comfy.py` → 调用 `_http_post_nojson('…/free' …)` 处。

## #5 端口守卫不能用"bind 失败"当判据

- **现象**：反复启动侧车，端口上堆了 4 个僵尸进程（2026-10-12 实测）。
- **真因**：Python 的 `HTTPServer` 默认 `allow_reuse_address = True`，Windows 上**允许多进程绑同一端口**，所以"bind 成功"不代表"没人在听"。
- **修法**：判据改成"主动连一次端口"（`create_connection` 成功即认为被占用），用 connect 结果决定是否启动。
- **代码锚点**：`sidecar_util.py` → `_port_open()`；`lib/index.js` → `portOpen()`。

## #6 编码补丁必须在"任何 import 期 print"之前执行

- **现象**：没有 `config.json` 的新机器上侧车启动即崩，`sidecar.err.log` 只有一行
  `UnicodeEncodeError: 'gbk' codec can't encode character '\u2717'`。
- **真因**：中文 Windows 下 stdout 被重定向到文件时 Python 按 locale 取 cp936，打印 `✗` / `✓` 直接抛异常；
  而 `sys.stdout.reconfigure(...)` 这段补丁在 0.5.3 拆模块时被挪到了文件**末尾**，`_load_cfg()` 在导入期就 print 了，补丁永远晚一步。
- **修法**：补丁放在 `import sys` 之后、任何模块级副作用之前；`sidecar_state.py` 自己再补一道。
- **代码锚点**：`expander.py` / `sidecar_state.py` 顶部 `reconfigure` 处。

## #7 同参数两次出图：文件 sha 不同，像素完全一致

- **现象**：固定 seed 跑两次，PNG 文件 sha256 不一样，但逐字节数相同（做过像素比对：差 0）。
- **真因**：ComfyUI 把含 `prompt_id` 的 workflow JSON 写进 PNG 的 `tEXt` 元数据，`prompt_id` 每次不同。
- **修法**：任何"回归/漂移检测"必须比**解码后的像素**（或像素 hash），**不能比文件字节**，否则 100% 误报。
- **代码锚点**：`lib/app.js` → `runRegression()`（当前只跑给人眼看，未做自动比对；将来加比对时按本条实现）。

## #8 侧车鉴权：`Origin` 是客户端可控头，不能用它证明来源

- **现象**：0.5.x 的鉴权对"带本机 Origin 的请求免 token"。看起来设防了，实际任何本机进程加一行
  `Origin: http://127.0.0.1` 就能拿到免 token 分支；而 `Access-Control-Allow-Origin: *` 又让**任何网站的预检都能通过**，
  于是恶意页面也能带自定义头打侧车（`/expand` 烧 API key、`/cards/write` 写盘、`/comfy/stop` 停服务）。
- **真因**：两层错——① 把可伪造的头当身份；② 回 `ACAO: *` 等于对所有站点开放自定义头。
- **修法**（两道叠闸，0.5.7）：
  1. **浏览器闸**：`ACAO` 只回显白名单 Origin（+ `Vary: Origin`）；面板请求统一带自定义头 `X-Console-Client`，
     自定义头会强制跨源**预检**，别的站点的预检被 ACAO 拒 → 浏览器根本发不出请求。
  2. **脚本闸**：无 Origin 的调用者仍必须带 `X-Console-Token`（要读盘才能拿到，抬高门槛）。
  并明确写下残余风险：**本机任意进程仍可同时伪造 Origin 与 X-Console-Client**——本地进程隔离只能靠 OS 账户权限，
  不在本插件能力范围内；token 的真实作用是"挡住不读盘的顺手调用"。
- **代码锚点**：`expander.py` → CORS 响应头块；`sidecar_auth.py` → `_auth_ok()`；`lib/app.js` → `CONSOLE_HEADERS` / `sidecarHeaders()`。

## #9 打包必须用白名单，不能用黑名单

- **现象**：0.5.3 的包里出现 `plugin\sidecar-token.txt`（43 字节真密钥）——因为在工作副本目录里起过一次侧车。
- **真因**：打包用 `Compress-Archive *` + 事后排除（黑名单），新出现的私件只要没被加进排除表就会进包。
- **修法**：打包只打**白名单**（`package.json.files` 列出的 + 套件根文档），并在打包后断言"包内不得含 token / `.pyc` / `*.bak*` / `config.json`"。
- **代码锚点**：`tools/build_suite.py`（打包器；不要再用 `Compress-Archive *`）。
